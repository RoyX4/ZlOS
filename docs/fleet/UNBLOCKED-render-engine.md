```c
/* gpu_surface.inc - GENERATED by gen_gpu_surface.py. Do not edit by hand.
 *
 * Gen9 RENDER_SURFACE_STATE field positions, lifted out of Mesa's own
 * decoder database - which ships ZLIB-COMPRESSED inside libgallium, which is
 * why twelve INTEL_DEBUG flags and four filesystem searches never found it.
 * Source: /usr/lib/x86_64-linux-gnu/libgallium-26.1.5-1.so
 *
 * The structure is 16 dwords. [...]
 * Each field is a dword index, a shift and a mask, so a builder writes
 *     dw[GPU_RSS_WIDTH_DW] |= (v & GPU_RSS_WIDTH_MASK) << GPU_RSS_WIDTH_SHIFT;
 * and cannot silently put a value in the wrong dword.
 */
#define GPU_RSS_DWORDS 16u
```

The agent additionally reports re-extracting the same genxml from

render target. *Those two checks are the agent's and were not re-run here* — the

## The honest remaining state

```
$ grep -rn "gpu_surface" kernel/*.c kernel/SOURCES kernel/tests/host/*.c
  (no output)
```

**Nothing consumes it yet.** So in this repo's own vocabulary the layout **exists** and
is not **reachable** — there is no builder that turns it into a surface state a batch
can point at.

That distinction is the entire point:

- The documented blocker is *"needs an external document this machine does not have."*
  **That is gone.** The data was extracted, generated into a header, and committed.
- What remains is *"nobody has written the builder yet"* — ordinary work, in-tree, with
  the field definitions sitting right there and a captured instance to check against.

Those are not the same kind of problem, and this project's own rule is to never let the
second be recorded as the first.

## What to change

1. **Correct `.ultra/STATE.md` §Open item 2 and its `Blocked:` line.** It is the file
   every session reads first, and it currently routes work away from the highest-value
   item in the project.
2. **Correct the four docs listed above**, or banner them at
   `docs/evidence/status-audits/STATE-OF-THE-PROJECT-2026-08-19.md` the way the other twenty-one planning documents are.
3. **Re-rank the next action.** `.ultra/STATE.md`'s current next step is to flash
   `zlOS-usb.img` and press `G` — which exercises the **blitter**, the engine measured at
   ~1× against the CPU. The render engine is the one worth 48×, and its four stated
   prerequisites — ring, pipeline, shader, surface state — are now all in the tree.
4. **Write the builder.** `gpu_surface.inc` gives dword/shift/mask triples for 16 dwords;
   `gpu_batch.inc:506-508` reportedly holds a correct captured instance. That pairing —
   a generator plus a known-good example — is the ideal shape for a host-side test that
   can be watched going red before any hardware is touched.

**Before any of it, fix [`CRITICAL-gpuring-bar-truncation.md`](CRITICAL-gpuring-bar-truncation.md).**
Every RCS register access goes through the same truncating `intel_mmio()` accessor as the
blitter ring.
