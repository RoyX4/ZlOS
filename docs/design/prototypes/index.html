zlOS desktop - sixteen directions

Sixteen complete replacements for the zlOS desktop, each a working interactive prototype rather than a picture. Windows focus, move and close; the overview and command palette open; the settings toggles and sliders change real values. Every colour is a :root custom property named after the design.h token it would become.

None of this is implemented in the kernel. design.h, ui.c, wm.c, uikit.c and kernel.zl are untouched on this branch. The reasoning is in deciding.md; the axis picker is decide.html.

Round one - the original four

PLATE light + dark

A printed technical document. Warm paper, black ink, hard 2px rules, one vermilion overprint. The left rail is a numbered register; the module grid is ruled onto the desk where you can see it. Focus knocks the header plate out to solid ink. Dark is ortho lith film.

Datum light + dark

Round two - six more

Blueline light + dark

An engineering drawing in diazo whiteprint. Blue line on white, no black anywhere, cyanotype as the other mode. All chrome collapses into a bottom-right title block. Window state is line type: present continuous, unfocused hidden, minimised phantom.

The mixes - graphite base carrying paper character

PRESSWORK dark primary

Graphite widened until a knockout fits, then PLATE's knockout taken whole. Same 7.133% of a plate as graphite, 4.63x the ratio inside it: it does not add a mark, it makes graphite's existing mark legible. Focus is a 54 L* excursion at 6.4796:1.

STOCK dark primary

Graphite's ladder untouched, and a vermilion overprint instead of a knockout - ink laid on top of the material rather than the material changing value, so the raking light never inverts. Focus costs 1.997% of a plate.

INKSTOCK dark primary

Two materials, both dark: warm screened stock for the user, cool flat plate for the machine, separated by hue and texture rather than luminance. Its own readout says so: NOT separated by luminance, by design.

Every prototype takes the same scene deep-links, on load and on hashchange: #desktop #overview #palette #files #monitor #settings #lock, each with -dark (or -light, for the dark-primary mixes) appended. shift+D toggles.

Each second mode is a second semantic ladder, not an inversion: :root[data-theme=...] overriding the base block with every custom-property name identical between the two, which is the shape ui_theme_init_q8() would need to map one set of role names onto two primitive ladders.

All sixteen have only ever been judged against headless browser renders, never against fb.c on a 2560x1440 panel. The prototypes flatter the target in at least one known way: CSS gives letter-spacing free, where fb_text_role cannot track text without a new primitive.
