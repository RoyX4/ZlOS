zlOS desktop / four directions

Pick one. Each row is a name, the pitch as written on that mockup, its palette, its mode, its one structural move, and a link to the full 1280x720 picture.

These are pictures, not ports. Every file is static HTML and CSS made to be looked at. None of it is zl, none of it runs on the compositor, and nothing here has been proven buildable against the real renderer. Treat them as paint, not as code.

A judged ranking across identity, buildability and regression risk came out: PLATE 24/30, Raking 20/30, Folio 20/30, Datum 14/30. That is one opinion scored on three axes, and Raking and Folio tie. It is information, not a verdict. The choice is yours. If the one you want to look at every day is the one that scored 14, pick that one and the score is wrong, not you.

zlOS is a printed technical document - warm paper, black ink, hard rules, one vermilion overprint - and the modular grid the windows are set on is ruled onto the desk where you can see it.

The layout grid is drawn on the desk itself, and every window snaps visibly onto it.

Folio
light mode  /  mock-folio.html

The desktop is a printed page: a warm paper ground with a real type area, a left margin rail carrying the running table of contents, windows as square-cornered sheets snapped to a 12-column grid, and every distinction made with weight, case, scale, rule-thickness and whitespace, never with colour.

Structural move

A left margin rail holds the running table of contents, and hierarchy is carried by type alone.

Datum
light mode  /  mock-datum.html

The desktop is an engineering drawing on warm paper, ruled from a single left datum edge, and the only dark material on screen is the machine itself - a full-height ink rail and a full-width raster strip that carry the five numbers zlOS alone can measure.

Structural move

Everything is dimensioned off one left datum edge, with a dark ink rail and a full-width raster strip as the only machine surfaces.
